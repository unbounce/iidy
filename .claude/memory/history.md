## Origin

No CODEOWNERS file has ever existed in the repo's history (searched: `git log -- .github/CODEOWNERS CODEOWNERS`, 0 results). No originating Jira ticket, RFC, or Confluence page for iidy's own creation was found, and Confluence has no page titled "iidy". Of the eight earliest rows in `summary ~ "iidy"`, one is a usage ticket against another service — `CNC-20`, "[New Stats] iidy - infrastructure work for Event Receiver" (2017-11-01) — and the other seven are iidy's own product backlog, all created 2017-11-22: `PS-84` "Create contributing.md for iidy", `PS-85` "Create a Code of Conduct document for iidy", `PS-86` "Improve test suite for iidy", `PS-87` "Create documentation for iidy", `PS-88` "Create reference implementations/demos for iidy", `PS-89` "Create documentation for developers who want to contribute to iidy", and `PS-90` "Add "--environments-file" option to iidy". Those seven post-date the first commit by four months, so they record work on an existing tool rather than a decision to build one.

The rationale is stated in the repo itself, in the README as it stood at the first commit (`git show cf4f1ac0:README.md`, 2017-07-20). That version frames iidy as a direct replacement for Ansible: "`iidy` is a replacement for our use of Ansible as a wrapper around CloudFormation," it "uses AWS ParameterStore to replace our use of Ansible Vault for encrypting secrets and ARNs," and its single binary is "simpler to install than Ansible's Python dependencies." It states "Migration from Ansible / Ansible Vault to `iidy` is mandatory" (emphasis in the original), targets "all production services migrated by the end of Sept 2017", answers "Who supports and maintains it?" with "Tavis.", and gives four reasons: Ansible is "an unnecessary layer above CloudFormation that has a bad UX for this use-case"; "we want to retire Ansible Vault as our use of it has some security issues"; developers "have not had a good onboarding experience learning Ansible and CloudFormation at the same time"; and "We do not have the bandwidth to support multiple tools."

The purpose statement has been reworded since. At `cf4f1ac0` it reads "`iidy` improves the developer experience with CloudFormation."; on `origin/master` as of 2026-08-26 it reads "iidy improves the developer experience with CloudFormation and CloudFormation templates," listing readable CFN feedback, AWS-profile support, changeset support, template validation, Parameter Store integration, and an optional YAML pre-processor as its features. The Ansible framing is absent from the `origin/master` README.
